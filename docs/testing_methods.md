# Сравнение методов тестирования ЛР №4

| Метод | Преимущество | Ограничение | Применение |
| --- | --- | --- | --- |
| Причинно-следственный анализ | Связывает вход, приоритет проверки и ответ | Число правил растёт с числом условий | Версия, форма матрицы, исход сравнения |
| Покрытие решений | Проверяет оба исхода ветвления | Скрывает значения отдельных условий | Принятие или отказ по версии |
| Покрытие условий | Проверяет оба значения каждого условия | Короткое замыкание может пропустить условие | Тип и значение версии |
| Комбинаторное покрытие | Выявляет взаимодействие условий | Число сочетаний растёт экспоненциально | Четыре логических сочетания и три наблюдаемых пути |
| Интеграционные проверки | Проверяют HTTP и связку модулей | Сбой сложнее локализовать | JSON, суммы и коды отказов |
| Регрессионные проверки | Защищают ранее подтверждённые результаты | Требуют поддержки при изменении требований | Главная или побочная диагональ больше |

Для выбора сценариев применяется таблица решений, для контроля ветвей используется coverage.
Для контракта сервера применяются интеграционные тесты, для двух исходов клиента настроен отдельный регрессионный запуск.
