# Обзор российских платформ для работы с Git

Рассмотрены три российские платформы для хранения исходного кода, контроля версий и совместной разработки. Обзор подготовлен по официальным материалам разработчиков.

## GitFlic

**Назначение:** размещение Git-репозиториев и организация командной разработки.

**Возможности:** публичные и приватные репозитории, команды и организации, задачи Issues, автоматические проверки и сборки CI/CD, хранение программных пакетов. Доступны облачная версия и установка на собственном сервере.

**Преимущества:** возможность выбрать способ размещения, совместная работа с кодом и автоматизация разработки на одной платформе.

**Ограничения:** установка на собственном сервере требует настройки и сопровождения инфраструктуры. При использовании облачной версии необходимо подключение к сервису.

**Реестр российского ПО:** запись №15861 от 09.12.2022. Функции и сведения о регистрации приведены на [официальном сайте GitFlic](https://gitflic.ru/).

## Deckhouse Code

**Назначение:** управление репозиториями и жизненным циклом программного обеспечения в корпоративной инфраструктуре.

**Возможности:** хранение кода, ветки и запросы на слияние, ревью изменений, управление доступом, задачи и конвейеры CI/CD. Решение основано на GitLab.

**Преимущества:** объединение инструментов совместной разработки, проверки и поставки ПО; разграничение прав доступа; интеграция с экосистемой Deckhouse.

**Ограничения:** развёртывание требует подготовки инфраструктуры Kubernetes и настройки зависимостей. Для небольшого учебного проекта такая установка может оказаться сложной. Это оценка применимости к данному проекту.

**Реестр российского ПО:** запись №27871 от 06.05.2025 указана на [официальной странице Deckhouse Code](https://deckhouse.ru/products/code/). Возможности описаны в [документации](https://deckhouse.ru/products/code/documentation/), порядок развёртывания — в [инструкции по установке](https://deckhouse.ru/modules/code/stable/).

## Сфера.Код

**Назначение:** совместная работа с исходным кодом и управление его версиями в корпоративной среде.

**Возможности:** Git-репозитории, ветки, коммиты и теги, запросы на слияние, комментарии к изменениям, защищённые ветки, разграничение ролей, зеркалирование и интеграции с внешними системами CI/CD.

**Преимущества:** размещение в инфраструктуре организации, управление доступом, настройка правил проверки и слияния изменений.

**Ограничения:** продукт поставляется для установки в инфраструктуре заказчика. Необходимы развёртывание, администрирование и настройка интеграций.

**Реестр российского ПО:** включение в Единый реестр российского ПО подтверждается [официальной страницей Сфера.Код](https://www.sferaplatform.ru/kod), где также описаны функции и модель поставки.

## Сравнение применимости

| Платформа | Оценка для проекта MatrixDiagonalsComparator |
| --- | --- |
| GitFlic | Облачная версия позволяет работать с учебным репозиторием без установки собственного сервера. |
| Deckhouse Code | Представляет интерес для корпоративной разработки и изучения инфраструктуры Deckhouse. |
| Сфера.Код | Подходит для изучения командной разработки в инфраструктуре организации. |

Для небольшого учебного проекта из рассмотренных вариантов удобнее начать с облачной версии GitFlic. Deckhouse Code и Сфера.Код целесообразно рассматривать при наличии собственной инфраструктуры и требований к корпоративной разработке. Этот вывод является оценкой на основе описанных способов поставки.
